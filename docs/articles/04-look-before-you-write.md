# 先看再写：给 Office 那一层换成原生工具调用，值不值

> AutoMan 技术文章 · 第 4 篇 / 共 5 篇

AutoMan 的 L2 这一层通过 COM 接口操作 Excel / WPS：打开工作簿、读区域、写公式、另存、导出。
从第一版起它的做法就很简单 —— **模型一次输出整组操作（一段 JSON），程序照单执行，执行结果不再回给模型**。

现在几乎所有模型都支持原生的工具调用（function calling）：把工具的名字、说明、参数格式随请求交给模型，
模型以结构化的调用作答，程序执行完把真实结果回喂，模型据此决定下一步。听上去全面更好。
这一篇是把它真的换上去、量一遍的记录：**在哪些任务上值、在哪些任务上不值、换的过程中挖出了什么。**

## 一、怎么比才说得清

**三条臂，不是两条。** 从"一次给齐的 JSON"到"原生调用 + 多轮回喂"，其实同时换了两样东西：
输出格式，以及有没有回路。只比两头，说不清改善来自哪一样。所以中间加了一条臂：

| 臂 | 做法 |
|---|---|
| json | 一次输出整组操作，执行结果不回给模型（原来的做法） |
| 原生单轮 | 原生调用，但只给一轮：所有调用一次给齐 |
| 原生多轮 | 原生调用，真实结果回喂，直到模型调用"完成" |

三条臂看到的是同一套工具（名字、说明、参数出自同一份定义，测试守着），同一条任务在三种方式下紧挨着跑。

**开发集和留出集分开。** 前两轮的改动都是看着失败改的，那些任务上的数字只能当开发集看。
从第三轮起，每轮开跑前另写两条任务、冻结（实现和任务文件都记 SHA-256，跑完复核一致），
**看过结果就降为开发集**，下一轮再写新的。两种集合的数字始终分开报，不合并成一个成功率。

**判据先自检。** 每条任务的判据都要过三个方向：空工作区判错、参考解判对、"凭习惯猜布局"的错误答案判错。
后来又加了一条"不该动的格子一个都没动"（下面第四节会讲为什么）。

## 二、结论取决于"表格长什么样"

任务分两类：**布局写明了的**（"在 D 列写公式，表头在第 1 行"），和**布局要读了才知道的**
（表头在第 3 行、编码在 B 列不在 A 列、汇总块藏在中间）。

| | json | 原生单轮 | 原生多轮 |
|---|---|---|---|
| 第三轮留出集（2 条 × 5 次） | 0/10 | 0/10 | **6/10** |
| 第四轮留出集（另 2 条 × 5 次） | 0/10 | 0/10 | **5/10** |
| 布局写明的 3 条（第四轮，开发集） | 15/15 | 5/15 | 15/15 |

两次留出集方向一致：**布局要读了才知道的任务上，只有多轮做得成** —— json 看不见表，只能猜，
猜错了也不知道；多轮先读、再写、读回核对。但两次留出集都是"一条任务贡献了大部分通过"，
样本很小，结论到"方向一致"为止，不到一个精确的百分比。

**布局写明了的任务上，多轮没有任何收益**，而 L2 那一步的 token 中位数贵约 21 倍、耗时约 2 倍。
贵的原因很具体：这个模型习惯**一轮只发一个调用**（打开 → 列表 → 读 → 读 → 写 …），
每一轮都要重发完整对话和十几个工具定义。提示词里写了"互不依赖的调用放在同一轮"，效果有限。

**只换格式、不给回路，比原来更差。** 原生单轮几乎每次只发一个调用就停了 —— 提示词明确要求一轮给齐，
模型照样一轮一个。在这个模型上，"格式稳定性"根本不是瓶颈（json 那侧几乎没有解析失败），回路才是。

## 三、换一个更强的模型呢

修完前几轮暴露的问题之后，拿三个模型各跑 11 条任务 × 3 次（其中 2 条是实现定稿后新写的题）：

| | glm-4.5-air | glm-5.3-flash | glm-5.3 |
|---|---|---|---|
| json | 9/33 | 9/33 | 9/33 |
| 原生多轮 | 29/33 | 33/33 | 33/33 |
| 其中 2 条新题（多轮 / json） | 6/6 / 0/6 | 6/6 / 0/6 | 6/6 / 0/6 |
| L2 一步轮数中位（多轮） | 9 | 5 | 5 |
| 平均每轮调用数 | 1.00 | 1.15 | 1.09 |

三件事：

1. **json 和模型无关，卡在结构上。** 三个模型都是 9/33，过的正好是布局写明的那 3 条。看不见表，换多强的模型也只能猜。
2. **更强的模型轮数少了一半、token 反而省了**（先把要读的一次读齐、几乎不报错），但单次调用要思考，**更慢**。
3. **"一轮一个调用"的习惯，更强的模型基本还在。** 真实任务里一轮多调用只占 8%～15%，几乎都是"两张表一起读"。
   探针那种玩具例子里三个模型都会并行发两个 —— 只看探针会得出错误结论。

## 四、两种方式都会改坏数据，方式不同

判据原先只看"该写的写对了没有"，不看"不该动的动了没有"。从轨迹里的每一次写操作反推落点、和原始数据比，
第三轮里两边各有 5 次改动了原有数据：**json 是因为看不见**，把公式写进了表头；
**多轮是看了之后数错一行、漏写表名**，压掉了别的数据 —— 其中一次判据照样通过。

回路给了模型改错的机会，也给了它更多乱动的机会。之后加的几道护栏，每一道都对应一次真实的事故：

- 覆盖已有数据先拦下。第一版让模型带一个 `overwrite: true` 表示"我知道"，结果它**几乎每次写入都带上**，
  连空格子也带 —— 模型能自己给自己的确认，就不是确认。改成"写出被覆盖格子现在的内容"，
  又被模型照抄拒绝信息里给出的内容绕了过去。**最后交给人**：和删除、提交走同一条确认通道。
- 工作簿有多张表时，写操作必须指定表；读回的每个值带上单元格地址，并提示"下面还有数据"。
- 公式算出 `#N/A` 这类错误值，算这次调用失败；不许拿数值盖掉公式；公式必须以等号开头。

## 五、A/B 顺带挖出来的东西

比两种方式，最大的收获反而是那些"**零报错、但整件事是错的**"缺陷：

- **写入多行区域只写进了一格。** pywin32 的晚绑定把 `Range.Resize(8, 1)` 解析成"取 Resize 再取第 (8,1) 个元素"，
  整块数组塞进了右下角那一格，函数照样返回"写入 8×1 区域"。这个 bug 从最早的版本就在。
  查了轨迹库：历史上的 json 运行从没用过多格写入，**已发表的数字不受影响**。
- **保存跑出了工作区。** 有一次 `Save()` 把整本工作簿存进了用户的「文档」目录，工作区里的文件停在半成品。
  COM 绕过了沙箱，原有的边界检查只管显式给出的路径。同样的操作连做 40 次没能复现；
  查不出根因时能做的是：**每次保存之后核对文档实际落在哪**，不在工作区就按越权处理。
- **凭空编了一张表。** 测试脚本的路径写错、工作区是空的，多轮模式新建了一个工作簿、编了一张预算表，
  报告"完成，结果正确"。现在任务点名的文件不在工作区、任务又没说要新建时，调模型之前就拒绝。
- 回滚时文件被 WPS 独占锁住，整次运行崩溃；轮数用完判失败，回滚删掉了正确的产物；
  导出的 PDF 扩展名是 `.xlsx` —— 都已修，都有测试，变异测试确认测试真能抓住。

## 六、最后的选择：按任务自动挑

既然结论取决于表格长什么样，那就**先看一眼表格再决定**。不调模型，用 openpyxl 读一下目标工作簿：
只有"不用按内容定位"的操作（导出、另存、重算），或者"任务写明了位置、而且表格是标准布局"时，一次给齐；
其余先看再写。一次给齐中途失败，就把文件还原成执行前的字节，改走多轮重做。

第二轮验证（17 条任务 × 3 次，其中 15 条是开发集、2 条是开跑前冻结的新题）：

| | json | 多轮 | 自动挑 |
|---|---|---|---|
| 开发集 15 条 | 16/45 | 44/45 | 44/45 |
| 新题 2 条 | 1/6 | 6/6 | 6/6 |
| L2 token 合计（17 条） | 6.4 万 | 60.5 万 | 43.9 万 |
| 整条任务耗时中位 | 10.7s | 21.2s | 12.4s |

自动挑的通过数和多轮一样，L2 的 token 少约四分之一、整条任务快不少；布局写明的那几条上它基本走一次给齐，
和纯 json 一样省，又能在 json 写错时兜回来。产品默认就用它，多轮那条路配 glm-5.3（三个模型里
可归因于模型的错误最少；同档的 glm-5.3-flashx 快一点、差距只有一次，不显著）。

改完之后，一次任务里各环节用的模型：

| 环节 | 模型 | 思考 |
|---|---|---|
| 规划 | glm-4.5-air | 关 |
| L1 写代码 | glm-4.5-air | 关 |
| L2 一次给齐 | glm-4.5-air | 关 |
| L2 先看再写 | glm-5.3 | 只能开，用最浅的一档 |
| L3 控件操作 | glm-4.5-air | 关 |
| L4 视觉定位 | glm-4.5v | 默认 |
| 终局判定 | glm-4.5-air | 关 |
| 确认撤不回的动作 | 人 | —— |

评测台保持显式：不给参数时仍是 json、两条路同一个模型 —— 以后的数字不会被产品默认值悄悄改掉。

## 小结

- "原生工具调用更先进"不是结论。**它的价值来自回路，不来自格式**；而回路只在"要先看才知道怎么写"的任务上值钱。
- 比较要有留出集，而且一组只能用一次；数字分开报，样本小就只说方向。
- 给模型一个能改错的回路，也就给了它更多犯错的机会。收益靠工具层的护栏拿住，提示词拿不住；
  护栏里最后一道永远是人。
